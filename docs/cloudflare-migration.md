# Cloudflare candidate (local preparation only)

The public source baseline is Vercel production deployment `dpl_3E66qq5PHJ9P4BnRwtrR6bWWn5qK`, commit `123958a846763ec78c5a6e5ccf75e5b0dea6160f`. Build the unchanged published snapshot with `npm ci --ignore-scripts && npm run build`. Serve `dist` through the Worker, including the existing appearance reader, not an HTML-only export. No administrative or Notion service is changed.

The Worker runs before asset lookup to preserve security headers, the apex-to-www redirect and the `/about` redirect. Production serves `/about/` as the actual about HTML, redirects `/index` and its slash/HTML variants permanently to `/`, and accepts both `/api/appearance` and `/api/appearance/`. Clean page and resource slash variants are served without redirects; HTML-extension variants redirect permanently even for missing paths, preserving the query string. Repeated slashes redirect permanently to their collapsed form before route handling. Both hostnames must be routed to this Worker at release. The existing Neon read-only connection string must be supplied as the server-only `HSC_APPEARANCE_DATABASE_URL` binding from the already provisioned credential through an authorized release process; it must never be committed, logged, exposed to a browser or substituted with a new secret. Without it the existing uncached default CSS is returned. Both selected site and CV appearance must be verified using that existing credential before any cutover. The CV itself remains on `cv.havesomecode.io` and is not migrated here.

Local validation: build, then `npx --yes wrangler@4.159.0 dev --local --ip 127.0.0.1 --port 8792`; run `node --test tests/integration/cloudflare.test.mjs` against the local runtime. A separate synthetic Neon response can be tested by running `npx --yes wrangler@4.159.0 dev --local --config tests/integration/wrangler-fixture.jsonc --ip 127.0.0.1 --port 8793` and `node --test tests/integration/selected.test.mjs`. The fixture credential is not a production credential and the upstream response is synthetic. No deployment is performed by these commands. Compare rendered public and local pages on desktop and mobile, as well as assets, redirects, nested 404, API and response headers.

Baseline observation on 10 November 2026: the built root and 34 other directly retrievable assets matched the public bytes; `about.html` instead redirects through `/about` to `/#about`. Production appearance returned `selected` for both site and CV. The local unconfigured reader correctly returns `fallback`; synthetic selected responses exercise the Worker adapter but do not prove production database connectivity. Brave 390px and 1440px comparisons used the current public site CSS injected only in the local comparison browser; this validates visual layout with identical selected CSS, not the live credential. Public CV returned HTTP 200 independently. Browser captures and comparison output are local evidence, not production changes.

Before an independently authorized release, verify the current public deployment and its selected CSS again, provision only the existing reader credential securely, confirm the full public hostname and apex routing and certificates, and repeat the runtime/browser checks on the exact reviewed candidate. Keep the Vercel deployment, domain settings and restricted reader intact. Rollback is to restore the prior apex/www DNS and routing to that exact retained Vercel deployment, allow DNS/TLS propagation, and recheck pages, appearance and CV; the release operator must capture exact previous DNS records and provider routing before changing them. Do not claim cutover or rollback readiness from this local candidate alone.
